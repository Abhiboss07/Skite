# Benchmark dataset

Two corpora, for two different purposes. Keeping them separate is the point of
this file.

```
test-dataset/
  synthetic/   60 generated samples + exact ground truth   → regression testing
  real/        photographs of actual drawings              → the numbers worth quoting
  results/     harness output, one JSON per run
```

## `synthetic/` — 60 samples

Generated by `test-dataset/generate.ts` from a seeded PRNG, so the corpus is
reproducible from the seed alone and the ground truth is exact — no annotator
drew a box by hand, the generator knows where every element is because it put it
there.

| Style | Count | What it imitates |
|---|---|---|
| `sketch` | 20 | A hand drawing photographed under uneven light: wobbling strokes, a shading gradient across the page, ±1.2° rotation, slight blur |
| `wireframe` | 20 | A clean ruled wireframe — straight lines, even lighting |
| `figma` | 20 | A vector export: hairline strokes, text as filled grey bars, images as solid fills |

Five layout archetypes, cycled across each style: split hero with a card row;
centred hero with four cards; stacked sections; a hero with a full-width image; a
two-column feature list.

**These are not real sketches, and results on them are not evidence that the
pipeline works on real ones.** Their value is that ground truth is exact and the
corpus never changes, which makes them a precise regression signal: if geometry
IoU drops two points after a change to the detector, that is a real regression
and not annotation noise. Treat the numbers as *upper bounds*.

Regenerate with:

```bash
node test-dataset/generate.ts
```

## `real/` — photographs of actual drawings

Empty in the repository, by design: a handful of photographs the author took
would be no more representative than the synthetic set, and would carry the
false authority of being "real".

**The fastest way to populate it is the annotation tool at `/annotate`.** Load a
photo, drag a box, pick a role, and press *Save to dataset* — it writes the
image, the truth JSON and the index entry in one step, so the harness picks the
sample up with no further work. Nesting is derived from containment rather than
entered by hand, using the same rule the pipeline's structure pass uses.

To add samples by hand instead, drop images alongside an `index.json` in the
same shape the generator writes:

```json
{
  "items": [
    { "id": "kitchen-table-01", "style": "sketch",
      "image": "kitchen-table-01.jpg", "truth": "kitchen-table-01.truth.json" }
  ]
}
```

and a `.truth.json` per sample:

```json
{
  "id": "kitchen-table-01",
  "style": "sketch",
  "canvas": { "w": 1440, "h": 1100 },
  "nodes": [
    { "id": "n1", "role": "navbar", "parent": null,
      "box": { "x": 64, "y": 40, "w": 1312, "h": 72 } }
  ]
}
```

Boxes are in a 1440-wide canvas space, not source pixels — the harness normalises
both sides to canvas fractions before comparing, so the annotation does not have
to match the photograph's resolution.

A useful evaluation set, in rough order of how much each will hurt:

- 10 clean hand-drawn wireframes on white paper
- 10 messy notebook sketches (ruled or squared paper, ink bleed)
- 10 whiteboard photographs (glare, marker of varying thickness, an angle)
- 10 simple Figma or Sketch exports

Annotating 40 samples is a few hours of work. It is also the only way to get a
number that means anything outside this repository.

## Running the harness

```bash
node scripts/evaluate.ts                      # synthetic, offline classifier
node scripts/evaluate.ts --set real           # once real/ is populated
node scripts/evaluate.ts --classifier vision  # needs ANTHROPIC_API_KEY
node scripts/evaluate.ts --limit 6            # quick pass while iterating
```

Output goes to `results/<set>-<classifier>.json` and a summary table is printed.

## Metrics

| Metric | How it is computed |
|---|---|
| **Layout fidelity** | `0.6·geometry + 0.25·order + 0.15·coverage` — the headline number |
| ↳ geometry | Mean IoU over matched regions, both sides normalised to canvas fractions |
| ↳ reading order | Normalised Kendall τ over matched regions only |
| ↳ coverage | Share of ground-truth regions matched at all (IoU > 0.3) |
| **Component accuracy** | Share of *matched* regions given the correct role |
| **OCR accuracy** | Mean character-level Levenshtein similarity over regions that carry text. `n/a` when the classifier cannot read — reported as absent rather than as zero |
| **Build success rate** | Share of runs whose generated code parses and passes the responsive lint |
| **Responsive pass rate** | Share of runs with no fixed pixel width and no unbreakpointed multi-column grid. A static lint, not a rendered test |
| **Generation time** | p50 and p95, not a mean — latency has a tail |

Ground truth is loaded *after* the pipeline runs and is never passed into it.

Two deliberate choices worth knowing about when reading a result:

- **`grid` and `card` are scored as the same role.** They describe the same drawn
  rectangle at different levels of interpretation, and the distinction has no
  effect on rendered output.
- **Order is scored over matched regions only.** A region that was never detected
  cannot be mis-ordered, and counting it in both coverage and order would
  penalise one failure twice.
